# 逐格確定性渲染：不用 flyTo，也不用 MediaRecorder

影片輸出時，每一幀都由我們自己的鏡頭函式 `cameraAt(segment, t)` 算出鏡頭位置，`jumpTo` 過去後等待地圖 `idle`（圖磚載入且繪製完成）才擷取畫面，再帶上精確時間戳送入 WebCodecs 編碼。我們不使用 MapLibre 的 `flyTo` 等依真實時間播放的動畫，也不提供 `MediaRecorder` 即時錄影作為備援。原因是：手機上編碼一幀可能要數十到數百毫秒，圖磚也常延遲載入，只要畫面跟著真實時間跑，成品就會卡頓或出現空白圖磚；改為逐格確定性渲染後，網路與裝置效能只會影響輸出要等多久，不會影響成品品質。

## Considered Options

- **直接呼叫 `flyTo` 並用 `MediaRecorder` 錄下畫布**：實作最簡單，但成品品質取決於當下的網路與效能，被否決。
- **WebCodecs 為主、`MediaRecorder` 為備援**（原 v1 規格）：備援路徑仍是即時錄影，會重新引入卡頓與空白圖磚，且不支援 WebCodecs 的瀏覽器已很少，因此不做備援，改為直接提示使用者更換瀏覽器。

## Consequences

- 運鏡曲線必須自行實作（參照 `flyTo` 所用的 van Wijk 平滑縮放公式），不能直接套用 MapLibre 內建動畫的參數。
- 預覽與輸出共用同一個 `cameraAt`：預覽以 `requestAnimationFrame` 即時驅動、可容許圖磚延遲；輸出則逐幀等待。
- 不支援 WebCodecs 的瀏覽器無法使用本工具。
- 輸出前需先跑一次圖磚預熱，以縮短正式輸出時間；預熱必須用與正式輸出相同的畫布尺寸，否則算出的縮放層級不同，預熱到的是用不到的圖磚。
- 地圖的載入與繪製一律由我們主動呼叫 `map.redraw()` 推進，不等 MapLibre 自己的 `load` 事件或 requestAnimationFrame：分頁在背景時 rAF 會暫停，曾因此輸出整支沒有底圖的影片。地圖真的載入失敗時必須明確報錯，不可默默輸出。
- 路線不放在 MapLibre 的 GeoJSON 圖層，而是投影後以 Canvas 2D 繪製：GeoJSON 每次更新都要等 Web Worker 重新切片，逐幀改變路線長度會讓每一幀多等一輪。
- 地圖固定 `pixelRatio: 1`，讓地圖畫布尺寸等於輸出尺寸，避免高 DPI 手機產生 3 倍大的 WebGL 畫布。
